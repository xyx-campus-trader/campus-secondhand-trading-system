## 修复添加轮播图接口400错误问题

### 问题分析

1. **日期类型字段处理**：虽然我们已经修改了Banner实体类，支持多种日期格式，但如果前端传入的是完全无效的字符串"string"，仍然会解析失败
2. **自增主键id处理**：addBanner方法中没有明确处理前端传入的id字段，可能会导致问题
3. **缺少请求参数校验**：没有对请求体参数进行校验，无法提供友好的错误信息
4. **缺少异常处理**：当请求参数格式错误时，返回的是默认的400错误，缺少具体的错误信息

### 解决方案

1. **修改BannerServiceImpl.java**：
   - 在addBanner方法中，明确将id字段设置为null，确保使用数据库自增主键
   - 这样可以忽略前端传递的id字段，无论前端是否传递，都不会影响数据库操作

2. **添加全局异常处理**：
   - 创建一个全局异常处理类，处理HttpMessageNotReadableException等异常
   - 当日期格式解析失败时，返回更友好的错误信息
   - 这样可以让前端开发者清楚地知道具体的错误原因

### 具体修改内容

* 修改BannerServiceImpl.java的addBanner方法：
  - 添加`banner.setId(null);`，确保忽略前端传递的id字段
  - 这样可以确保使用数据库自增主键

* 创建全局异常处理类：
  - 新增`src/main/java/com/dnui/campussecondhand/user/exception/GlobalExceptionHandler.java`
  - 添加`@RestControllerAdvice`注解，处理全局异常
  - 添加`handleHttpMessageNotReadable`方法，处理日期格式解析失败的情况
  - 返回具体的错误信息，包括"日期格式错误，请使用正确的日期格式"

### 预期效果

1. 添加轮播图接口可以正确处理前端传入的各种情况
2. 当前端传入无效的日期字符串时，返回友好的错误信息
3. 无论前端是否传递id字段，都不会影响数据库操作
4. 接口测试可以顺利通过

### 代码示例

```java
// 修改后的addBanner方法
@Override
public AjaxResult addBanner(Banner banner) {
    // 忽略前端传递的id和createTime字段，使用数据库自增主键和自动生成的创建时间
    banner.setId(null);
    banner.setCreateTime(null);
    int rows = bannerMapper.insert(banner);
    if (rows > 0) {
        return AjaxResult.success("添加成功", banner);
    }
    return AjaxResult.error("添加失败");
}

// 全局异常处理类示例
@RestControllerAdvice
public class GlobalExceptionHandler {
    @ExceptionHandler(HttpMessageNotReadableException.class)
    public AjaxResult handleHttpMessageNotReadable(HttpMessageNotReadableException e) {
        return AjaxResult.paramError("请求参数格式错误，请检查日期字段格式是否正确");
    }
}
```
