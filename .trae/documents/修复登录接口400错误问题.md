## 修复获取用户信息接口401错误问题 - 最终方案

### 调整说明

根据用户要求，过期时间仍然设置为7天，不修改为2小时。

### 问题分析

1. **当前问题**：获取用户信息接口返回401未授权错误

2. **根本原因**：
   - 用户访问的接口是 `/api/user/info`，但实际实现的是 `/api/user/me`
   - JWT工具类不符合配置要求
   - 拦截器配置可能存在问题

3. **详细分析**：
   - **接口路径不匹配**：用户访问 `/api/user/info`，但UserController中实现的是 `/api/user/me`
   - **JWT工具类不符合要求**：
     - 密钥使用随机生成的Key，不是固定的Base64编码字符串
     - 缺少 `createToken(Long userId, String role)` 方法
     - 当前实现的是 `generateToken(Long userId, String username)`
   - **拦截器配置**：拦截器配置了 `/api/user/me`，但没有配置 `/api/user/info`

### 修复方案

1. **修复JWT工具类**：
   - 使用固定的Base64编码字符串作为密钥
   - **保持过期时间为7天**（根据用户要求）
   - 实现 `createToken(Long userId, String role)` 方法
   - 保留原有 `generateToken` 方法的兼容性

2. **统一接口路径**：
   - 将UserController中的 `/api/user/me` 接口重命名为 `/api/user/info`
   - 删除重复的接口实现

3. **更新拦截器配置**：
   - 将拦截器配置中的 `/api/user/me` 替换为 `/api/user/info`

### 修改内容

1. **文件**：src/main/java/com/dnui/campussecondhand/user/util/JwtUtils.java
   - 修改密钥为固定的Base64编码字符串
   - **保持过期时间为7天**
   - 实现 `createToken(Long userId, String role)` 方法

2. **文件**：src/main/java/com/dnui/campussecondhand/user/controller/UserController.java
   - 将 `/api/user/me` 接口重命名为 `/api/user/info`
   - 更新Swagger注解

3. **文件**：src/main/java/com/dnui/campussecondhand/user/config/WebMvcConfig.java
   - 将拦截器配置中的 `/api/user/me` 替换为 `/api/user/info`
