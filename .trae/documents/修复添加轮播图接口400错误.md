## 修复添加轮播图接口400错误

### 问题分析

1. **日期格式不匹配**：Banner实体类中的日期字段使用了`@JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss", timezone = "GMT+8")`注解，指定了日期格式为"yyyy-MM-dd HH:mm:ss"，但测试时发送的是ISO格式的日期字符串（"2025-12-12T09:08:00.315Z"）

2. **不必要的字段传递**：createTime字段是数据库自动生成的（DEFAULT CURRENT_TIMESTAMP），不应该由前端传递

3. **JWT拦截器通过**：日志显示JWT令牌验证成功，拦截器通过，所以400错误不是认证问题

### 解决方案

1. **修改Banner实体类**：
   - 更新`@JsonFormat`注解，支持多种日期格式，包括ISO格式
   - 或者，使用`@JsonDeserialize`和`@JsonSerialize`注解来处理多种日期格式
   - 或者，修改日期格式为ISO格式，同时兼容原有的"yyyy-MM-dd HH:mm:ss"格式

2. **修改BannerServiceImpl.java**：
   - 在`addBanner`方法中，忽略前端传递的createTime字段，将其设置为null，让数据库自动生成
   - 这样可以避免前端传递不必要的字段

### 具体修改内容

* 修改Banner实体类中的日期字段注解：
  - 将`@JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss", timezone = "GMT+8")`
  - 改为`@JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss", timezone = "GMT+8", shape = JsonFormat.Shape.STRING, lenient = OptBoolean.TRUE)`
  - 添加lenient = OptBoolean.TRUE属性，允许宽松的日期格式解析

* 修改BannerServiceImpl.java的addBanner方法：
  - 在调用mapper.insert之前，将banner.setCreateTime(null);
  - 这样可以忽略前端传递的createTime字段，使用数据库自动生成的值

### 预期效果

1. 添加轮播图接口不再返回400错误
2. 支持多种日期格式，包括ISO格式和"yyyy-MM-dd HH:mm:ss"格式
3. createTime字段由数据库自动生成，不受前端传递值的影响
4. 所有轮播图相关接口都能正常工作

### 代码示例

```java
// 修改后的Banner实体类日期字段注解
@JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss", timezone = "GMT+8", shape = JsonFormat.Shape.STRING, lenient = OptBoolean.TRUE)
private Date startTime;

// 修改后的addBanner方法
@Override
public AjaxResult addBanner(Banner banner) {
    // 忽略前端传递的createTime字段，使用数据库自动生成的值
    banner.setCreateTime(null);
    int rows = bannerMapper.insert(banner);
    if (rows > 0) {
        return AjaxResult.success("添加成功", banner);
    }
    return AjaxResult.error("添加失败");
}
```
